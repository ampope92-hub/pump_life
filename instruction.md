We rebuild and lease centrifugal pumps, and the mechanical seal is what kills them. I need a seal-life estimate for a batch of pumps we're quoting service contracts on, because right now we're guessing and losing money on the ones that come back early. `/app/data/train.csv` is everything the maintenance system knows about the pumps we've had in service — how each one was set up and run, and where it got to. `/app/data/test_features.csv` is the quote batch, same setup columns. `/app/data/README.md` explains the columns and how the maintenance export was pulled.

Our tooling is Rust, so this has to live there — there's a Cargo project started for you at `/app/predictor` with `smartcore` and `csv` already wired into `Cargo.toml`. Fill in `src/main.rs` so that running it reads both CSVs, fits whatever model you think will hold up, and writes `/app/predictions.csv` with exactly two columns, `pump_id` and `life_days` — one row for every `pump_id` in `test_features.csv`, header included, any order. `life_days` is the seal life you expect from that pump in days, counted from install. The box is offline: the crates already in `Cargo.toml` are cached locally at the versions pinned in `Cargo.lock` so builds work, but you can't pull in new ones.

About the grading: we delete whatever `predictions.csv` is sitting there, run `cargo run --release` in `/app/predictor` ourselves, and score the file that comes out — so it has to work from a clean build. The quote batch is a cohort we've since run all the way to seal failure, so we have the real numbers, and your estimates get scored against them: R² has to reach at least **0.33** before we'd price contracts off this. The last go at this came back with an average predicted life well under what the pumps actually delivered, which is exactly the kind of thing that has us quoting too much service, so the bar is checked on the real lives and nothing else.
